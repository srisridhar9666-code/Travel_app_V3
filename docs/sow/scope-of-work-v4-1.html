This document represents the complete, fresh, and unified Master Scope of Work for Sriyatra, the enterprise field logistics, travel fulfillment, vehicle operations, and employee expense reimbursement platform for DesignBoxed Innovations Pvt. Ltd. It provides a comprehensive, end-to-end specification of all system capabilities, workflows, user roles, policies, and extended operational features.

Platform Architecture Overview: (1) Six discrete role portals, (2) Universal mandatory two-tier approval (Manager → Admin → Vendor), (3) Full Campaign and Team management by Managers, (4) Hotel occupancy evaluation (Single vs. Double default and user profile entitlement), (5) Saved Hotels Directory with auto-save & vendor proposals, (6) Exact same-gender co-stay matching, (7) Manual hotel check-in/out verification, (8) Daily cab hire telemetry with start/end meter photos, auto-timestamps, and reverse geocoding, (9) Telemetry policy governance with missed-photo regularization and booking locks, (10) Comprehensive expense reimbursements with food flat ₹400/day across all cities, manager endorsement, and finance settlement, (11) Vendor portal invoicing with Finance pre-verification and Super Admin approval, (12) In-app contextual bug reporting system, (13) Tamper-evident cryptographic audit logging.

1. User Hierarchy & Role-Based Access Control (RBAC)

The platform establishes six distinct, ranked user tiers, each with dedicated login credentials, scoped views, operational queues, and permission boundaries:

Role User Type Key Responsibilities & Permissions
1. Users (Ground Staff) Field personnel & team members (~100 staff) Raise requests for Flights, Trains, Buses, Cabs, and Hotels; choose hotel from vendor proposals; select room-sharing with same-gender colleagues; perform manual hotel check-in/out; upload cab start/end odometer photos; submit reimbursement claims with bills (Food flat ₹400/day, transit/auto, tolls/parking); submit in-app bug reports with screen context.
2. Managers Field Managers & Team Leads Mandatory Level-1 Approver for all team requests; Full Campaign Control (create, edit, pause, delete campaigns); Full Team Control (add, edit, delete team members); evaluate Single vs. Double hotel occupancy; review and endorse team reimbursement claims; inspect team rosters and itineraries; authority to unlock telemetry missed-photo locks.
3. Vendors Contracted travel agents, hotel partners, cab fleets Dedicated portal; receives approved bookings; proposes 2–5 hotel options with addresses/amenities (or quick-select from Saved Hotels Directory); assigns vehicle/driver for cabs; uploads booking vouchers and e-tickets; queries eligible un-invoiced trips and submits vendor invoices.
4. Finance Team Accounts & Finance Officers Dedicated audit queue for employee reimbursement claims; enforces policy rate caps (Food flat ₹400/day); approves/partially approves/rejects claims; issues disbursements and records bank UTR/transaction references; pre-verifies vendor invoices against cab telemetry KM and hotel folio bills.
5. Admin Operations & Travel Desk (~10 staff) Mandatory Level-2 Approver; confirms occupancy decisions; dispatches approved requests to vendors; manages Saved Hotels Directory, Tenant Settings, departments, and city tier policies; manages bug reports; direct booking fallback via Gemini AI.
6. Super Admin Executive Leadership System governance; final sign-off on Finance-verified vendor invoices; user role administration; configuration of policy limits and city categories; tamper-evident audit ledger inspection and data purge schedules.

1.1 Sign-In, Accounts & Security

  • No Self-Registration: All user accounts are provisioned by an administrator. Single-use invitation link (valid 72 hours) dispatched via email or shared over WhatsApp/SMS.
  • Password Policy: Minimum 10 characters. Self-service reset link valid for 2 hours. 5 consecutive incorrect attempts lock the account for 15 minutes. Sessions last 8 hours.
  • Tab Isolation: Browser tabs maintain independent sessions, allowing administrators to test employee-facing workflows concurrently.
  • Theme & Devices: Native Light, Dark, or System theme persisted per user across all devices. Mobile-first responsive layout with full desktop view option on mobile devices.
  • Request Sorting: Request queues strictly display the newest requests first (descending ID).

2. Campaign & Project Management

  • Full Campaign Lifecycle Control: Managers and Admins have complete control to create, edit, pause, complete, and delete campaigns. Campaigns with historical requests can be archived or restored.
  • Automated Campaign Codes: Generated automatically in the format CMP-YYYY-NNNN and cannot be manually edited.
  • Mandatory Request Tagging: Every travel, cab, hotel, and reimbursement request must be tagged to an active campaign. An emergency option (*"Other - not yet listed"*) allows typing a campaign title so field work is never blocked.
  • Campaign Financials: Real-time analytics on deployed staff, booked journeys, hotel nights, and total spend (travel, cab, hotel, reimbursements) per campaign.
  • Departments Master: Admins maintain department hierarchies for cross-departmental cost filtering.

3. Team Management & Organizational Hierarchy

  • Single-Tier Hierarchy: Each ground staff member reports to one manager (*"Reports to"*). Reassignment occurs seamlessly if a manager leaves or changes role.
  • Autonomous Team Control for Managers: Within the Manager Portal (*"My Team"*), managers directly add new members, edit member details, and remove/delete members from their roster.
  • Field Designations: Standard designations — Executive, Team Lead (TL), and Manager — define operational hierarchy and reporting structure.
  • Hotel Occupancy Entitlement: Configurable on user profiles (SINGLE or DOUBLE), enabling tailored default stay privileges.

  • Mode & Class Rules:

    • More than 8 hours or > 500 km: Flight (Economy Class).
    • Flight, train, and bus bookings follow the identical mandatory manager → admin → vendor workflow as hotels and cabs.
  • Lodging Ceilings (Exclusive of Taxes):

  • Daily Food Allowance (Employee incurred, claimed via reimbursement): Flat rate of ₹400 / day across all cities. Actual itemized food bills required.
  • Local Public Conveyance: Auto/rickshaw up to ₹150 / day without bills; amounts above ₹150 require receipts. Cabs reimbursed at actuals with receipts. Tolls and parking reimbursed at actuals with receipts.

5. Request Management (Field Employees)

  • Multi-Category Request Form: Long-distance travel (Flight, Train, Bus), Cabs, and Hotels.
  • Group Requests & Co-Travelers: One employee can raise a request for a team by tagging colleagues. Each traveler forms an independent decision row.
  • Edit Window: A request remains freely editable while all travelers are in PENDING status. Once any manager/admin action occurs, the request locks. Every edit writes a revision diff.
  • Conflict Detection: Checks proposed dates against existing itineraries (hotel by night, journey by closed window, cab sharing day with flight/train is exempt). Clashing requests warn the user; approvers must enter an audited justification to override.
  • Cancellations & Extensions: Immediate self-cancellation before decisions; formal *"Ask to Cancel"* after approval/booking. Cabs can be extended by an additional day upon administrative approval.

6. Universal Mandatory Two-Tier Approval Pipeline

Every booking request (Flight, Train, Bus, Cab, Hotel) must complete a mandatory two-step approval before being dispatched to vendors:

1
Ground Staff Submits Request
Request is linked to an active campaign with destination, dates, travel reason, and urgency. For hotels, default requested occupancy is Single.
2
Level-1: Manager Approval (Strictly Mandatory)
The employee's manager reviews the request. For hotels, the manager determines Single or Double occupancy eligibility. Manager approves or rejects with comments, auto-stamping manager_reviewed_at.
3
Level-2: Admin Approval
Admin reviews the manager-approved request, validates policy compliance, confirms/overrides occupancy, and grants final approval with a logged reason.
4
Vendor Dispatch & Fulfilment
Request is routed to the designated Vendor portal to initiate hotel option submission, cab driver assignment, or flight/train ticket booking.

7. Hotel Sourcing, Occupancy & Saved Hotels Directory

  • Occupancy Decision: Defaults to Single Occupancy (or user profile entitlement). Evaluated by Manager or Admin based on seniority, campaign budget, or paired travel. Enforces city rate caps.
  • Saved Hotels Directory: Central directory of pre-contracted hotels with verified amenities, standard room rates, address, and landmark. Vendors or admins can auto-fill options with one click.
  • Vendor Hotel Proposals & Auto-Save: Vendor submits 2 to 5 available hotel options in the destination city. Any newly proposed hotel is automatically saved to the master directory.
  • Employee Selection: The employee receives a notification and selects their preferred hotel from the vendor's proposals.
  • Same-Gender Room Sharing Engine: If Double Occupancy is active, the system queries colleagues staying at that exact hotel during overlapping dates.
    • Strict Safety Filter: Only colleagues of the identical gender (Male with Male, Female with Female) are displayed. Cross-gender pairing is strictly prohibited.
    • Employee selects roommate, opts for an individual room (if eligible), or requests Admin allotment.

8. In-Transit & On-Site Verification Telemetry

8.1 Daily Cab Hire Telemetry (Whole-Day Dedicated Cab)

Cabs are deployed on a whole-day basis where the car remains dedicated to the employee throughout their working hours. Typically, start location and drop location are identical (hotel in morning → field duties → hotel in evening):

A
Morning Start of Day: Meter Photo & Timestamp
When meeting the cab at the hotel, the employee clicks Start Trip, captures an odometer photo (live camera or upload), and enters starting KM. The system auto-captures non-editable IST timestamp, GPS, and reverse-geocoded location name.
B
Evening End of Day: Meter Photo & Timestamp
Upon returning to the hotel at the conclusion of field work, the employee clicks End Trip, captures the final odometer photo, and enters ending KM. The system auto-captures departure timestamp, GPS, and location name.
C
Automated Telemetry Audit
The system computes Total Distance = End KM − Start KM and Duration = End Time − Start Time. Both meter photos, location names, and readings are displayed side-by-side in Admin and Finance screens to audit against vendor invoices.

8.2 Manual Hotel Check-In / Check-Out Verification

  • Manual Check-In: Upon arrival at the hotel, the employee clicks Check-In. The system records arrival timestamp (IST), GPS coordinates, and location name. The employee enters their assigned room number.
  • Manual Check-Out: On departure, the employee clicks Check-Out, auto-capturing departure time and GPS. The employee uploads a photo of the Final Hotel Folio / Bill (confirming company entity name and employee name).
  • Reimbursement Prompt: Submitting check-out prompts the employee to raise food or local conveyance reimbursement for the completed stay.

8.3 Telemetry Policy Governance & Booking Locks

  • Tenant Policy Settings: Organization-wide settings govern require_telemetry_checkout and max_monthly_missed_photos (default: 5).
  • Booking Lock: If an employee exceeds the monthly missed checkout/telemetry threshold, the system blocks them from booking subsequent trips.
  • Manager / Admin Unlock: Managers or Operations Admins can force-close unclosed trips or unlock employees with an audited reason.
  • Live Telemetry Badges: Requests display real-time status badges for hotel_verification_status and cab_telemetry_status.

9. Post-Travel Expense Reimbursement Module

Company directly books and pays for intercity travel and hotels. Daily food, parking, tolls, and local public transit are incurred directly by the employee and reimbursed under policy caps:

  • Eligible Categories:
    • Daily Food Allowance: Flat rate of ₹400 / day across all cities. Itemized food bills mandatory.
    • Local Transit: Metered auto/rickshaw up to ₹150/day without bills; claims > ₹150 require receipts. Tolls and parking reimbursed at actuals.
    • Miscellaneous Field Expenses: Incidental field work supplies with receipts and written justification.
  • Comprehensive Reimbursement Form:
    • Header Details: Claim ID (EXP-YYYY-NNNN), employee name/code, department, linked campaign, linked travel booking ID, destination city, travel date range.
    • Payment Context: Employee payment mode (ONLINE or CASH), expense classification (FOOD, TRAVEL, OTHERS), remarks.
    • Payout Bank / UPI Details: UPI ID, Bank Name, Account Number, Account Holder Name, IFSC Code, and consolidated bill upload.
    • Itemized Lines: Date, category, vendor name, bill number, claimed amount, receipt upload.
    • Manager Endorsement: Manager records review notes, timestamp, and sets manager_endorsed = True.
    • Finance Audit & Settlement: Finance team verifies receipts against policy limits, enters deduction notes, records payment date, mode (NEFT/RTGS/UPI), and Bank Transaction UTR Number, marking the claim SETTLED.
    • CSV Import/Export: Full spreadsheet export and bulk import support.

10. Fulfillment, Ticketing & AI Extraction

  • Action Queue: Segmented tabs for Awaiting, Partially Approved, Approved, Ready for Vendor, Booked, Rejected, and Cancelled. Sorted strictly newest first.
  • Vendor Portal Fulfillment: Hotel vendors submit room options (with Saved Hotel selection) and final vouchers; Cab vendors record car and driver details; Ticketing partners upload confirmed e-tickets.
  • Direct Admin Booking & Gemini AI Extraction: For direct desk bookings, admins upload raw tickets/vouchers. Google Gemini AI parses PNR, carrier, flight/train numbers, dates, times, and hotel names. Configurable via Tenant Settings (ai_ticket_autofill_enabled). Details are pre-filled for administrative check; the model never auto-books on its own.
  • Ticket Delivery: Booking emails carry the confirmed ticket as an attachment (manager in CC). Employees can download their tickets from My Requests at any time.

11. Vendor Invoicing & Multi-Tier Verification

  • Vendor Portal Invoicing: Contracted vendors query eligible completed trips (/invoices/eligible) for their assigned vendor ID in a given period and compile invoice INV-YYYY-NNNN. Total is calculated strictly from verified trip costs.
  • Finance Pre-Verification: Finance Officer audits the submitted invoice against actual cab telemetry photos and hotel folio bills, recording an audited verification comment (/invoices/{id}/verify).
  • Super Admin Final Approval: Super Admin approves invoice (/invoices/{id}/approve), freezing costs and locking trips from duplicate billing. Downloadable as CSV or printable PDF.

12. Employee Management & Profiles

  • Team Directory: Comprehensive employee roster with CSV bulk import and preview. Fields: Name, Email, Mobile (unique 10-digit), Role, Designation, Department, Reports-To Manager, Base Location, Gender, Hotel Occupancy Entitlement (SINGLE / DOUBLE), Employee Code, and Status.
  • Identity Documents & Encryption: Aadhaar, PAN, Passport numbers stored with Fernet AES-256 encryption. Scans stored outside the web root. Viewing sensitive data writes an audited VIEW_SENSITIVE row. Automatic 90-day post-exit purge.
  • Travel History: Timeline view per employee showing all historical journeys, hotel stays, and cab companions.

13. In-App Bug & Issue Reporting System

  • Floating Bug Widget: Accessible across all screens to all users (Ground Staff, Managers, Vendors, Finance, Admin).
  • Automatic Context Capture: Captures page URL, page title, user role, and browser environment automatically.
  • Submission & Screenshot: User enters issue description and attaches screenshot.
  • Administrative Bug Dashboard: Dedicated screen for Admins and Super Admins (/bug-reports) with status tracking (OPEN, RESOLVED), resolution notes, resolving admin, and timestamps.

14. Dashboard, Analytics & Reporting

  • Live Operations Dashboard: Visual breakdown of deployed staff by state and campaign, pending queues, and system alerts.
  • Departmental Analytics: Trips, headcount, hotel nights, and booked expenditures by department.
  • Cost Analytics: Expenditures filterable by campaign, location, and date range across Travel, Cabs, Hotels, and Reimbursements.
  • Telemetry Audit Reports: Cross-references cab meter actual KM against vendor billed KM to detect overbilling.
  • Travel Logs: Complete historical log of all movements, filterable and exportable to CSV.

15. Notifications, Reminders & Communications

  • In-App & Email: Real-time notification center plus Gmail SMTP delivery. Decisions, bookings (with ticket attached), room-sharing notices, and pending alerts.
  • Automated Reminders: Travelers notified 2 days before a trip; managers and admins reminded of requests pending over 3 days.
  • Delivery Ledger: Audit log tracking recipient, timestamp, delivery status (`SENT`, `FAILED`, `SUPPRESSED`), and server responses.

16. Security & Cryptographic Audit Logging

  • Cryptographic Append-Only Activity Log: Every event (creation, edits, manager L1 approvals, admin L2 approvals, vendor hotel submissions, employee hotel picks, manual check-in/outs, cab odometer captures, finance reimbursement audits, disbursements, bug reports) is recorded in an immutable ledger.
  • Tamper-Evident Hash Chaining: Each row contains the SHA-256 hash of the previous row, verified via the admin console. Append-only database user grants in production (`INSERT` and `SELECT` only).
  • Rate Limiting & Hardening: Per-IP rate limiting on authentication endpoints, secure HTTP headers, and environment-based credential management.

17. Platform Architecture & Delivery Specifications

  • Frontend: Modern responsive single-page application built with React, TypeScript, Tailwind CSS, and Vite.
  • Backend: High-performance RESTful API engineered with Python FastAPI, Pydantic data schemas, and SQLAlchemy ORM.
  • Database: MySQL 8 Enterprise Database with automated Alembic schema migrations.
  • Document & Image Storage: Secure localized storage outside the web root, with cloud storage abstraction ready for Google Cloud Storage (GCS).
  • Deployment: Multi-container Docker architecture (docker-compose.yml), containerized for production on Google Cloud Run or Linux VM hosting.
  • Quality Assurance: Over 1,000 automated unit, API, and integration test suites, alongside end-to-end database build verification.
